# 耀坤 S3 适配说明（ESP-FC 飞控 · 耀坤整理版）

> 本文记录 ESP-FC **耀坤整理版**相对上游 `rtlopez/esp-fc` 的全部改动、每个改动的**根因分析**与**验证方法**。  
> 读完本文你应该能回答三个问题：改了什么、为什么必须改、怎么确认改对了。

- **上游项目**：<https://github.com/rtlopez/esp-fc>（MIT，`(c) Ramon Lopez`）
- **整理版仓库**：<https://github.com/YaoKunS/esp-fc>（分支 `yaokun-organized`）
- **版本**：**v1.0**
- **硬件**：耀坤 S3 无人机（ESP32-S3，立创 R8N8 / Supermini N4R2 两种模组）
- **电机**：4 × **8520 空心杯有刷电机**（🔴 有刷，不是无刷）
- **引脚依据**：《耀坤S3无人机引脚定义.xlsx》，逐行核对

---

## 一、一句话结论

上游 ESP-FC 的 ESP32-S3 板级定义是给**通用 S3 模板板**（Lolin S3 Mini 一类）写的，  
里面全是占位引脚（电机 39/40/41/42、SPI 12/11/13、I2C SCL=10），  
**与耀坤 S3 的 PCB 布线一对不上**。直接烧上游固件的结果是：  
四电机没输出、IMU 读不到、GPIO39 蜂鸣器被当成电机脚、电池电压读数偏差一倍。

本版**新增独立板级定义 `TargetESP32s3YaoKun.h` + 独立编译环境 `esp32s3_yaokun`**，  
把引脚逐条对齐 xlsx 清单，并针对 8520 **有刷**电机强制启用 PWM（BRUSHED）输出协议。  
上游 `[env:esp32s3]` **一行未改**，两套固件可随时切换对比回归。

## 三、引脚对照表（逐行取自 xlsx）

### 3.1 电机输出（🔴 8520 空心杯有刷电机）

| 输出通道       | GPIO   | PCB 丝印  | 位置    | 上游模板值 |
| ---------- | ------ | ------- | ----- | ----- |
| `OUTPUT_0` | **6**  | MOT1_FR | 右前 FR | 39 ❌  |
| `OUTPUT_1` | **5**  | MOT2_RR | 右后 RR | 40 ❌  |
| `OUTPUT_2` | **15** | MOT3_RL | 左后 RL | 41 ❌  |
| `OUTPUT_3` | **16** | MOT4_FL | 左前 FL | 42 ❌  |

> ⚠️ **上游把 GPIO39/40/41/42 当电机脚**，而耀坤板上  
> **39 = 蜂鸣器、41 = 红灯、42 = V2 板的 MPU6500 片选**。  
> 不改的后果不是"电机不转"这么轻 —— 是**蜂鸣器常鸣 + IMU 片选被拉乱**。

### 3.2 IMU（MPU6500 走 SPI，MPU6050 走 I2C）

| 功能       | GPIO   | 备注                        |
| -------- | ------ | ------------------------- |
| SPI_SCK  | **38** | xlsx 第 6 行                |
| SPI_MOSI | **18** | xlsx 第 5 行                |
| SPI_MISO | **21** | xlsx 第 4 行                |
| GYRO_CS  | **17** | 🔴 **V1 板实测值**；V2 板按表为 42 |
| I2C_SCL  | **8**  | 🔴 SCL=8、SDA=9，别写反        |
| I2C_SDA  | **9**  | MPU6050 / BMP280 / 磁力计    |
| BARO_CS  | -1     | 本板未接气压计                   |

> 🔴 **V1 / V2 板只差这一个 CS 引脚**（17 ↔ 42）。SCK/MOSI/MISO 两版一致。  
> 换板型只需改 `TargetESP32s3YaoKun.h` 里 `ESPFC_SPI_CS_GYRO` 这一行。

### 3.3 遥控与串口

| 用途         | GPIO      | 说明                                |
| ---------- | --------- | --------------------------------- |
| SBUS 输入    | **1**     | xlsx EXT01；同时也是 `ESPFC_INPUT_PIN` |
| ELRS 预留 TX | **11**    | 飞控 → 接收机                          |
| ELRS 预留 RX | **12**    | 接收机 → 飞控                          |
| UART0(MSP) | **43/44** | 地面站主串口，115200 8N1                 |
| USB CDC    | —         | S3 原生 USB，虚拟 COM 口                |

> ⚠️ **ELRS 接收机输出 CRSF，不是 SBUS**。本版 UART2 虽已按 xlsx 接线定义，  
> 但**必须先在地面站里把该串口协议改成 CRSF** 才能用。  
> 第一次上手建议直接用 SBUS 接收机（GPIO1），少一个变量。

### 3.4 其它

| 功能      | GPIO   | 备注                                    |
| ------- | ------ | ------------------------------------- |
| VBAT 采样 | **2**  | 1:2 分压 ⇒ `ESPFC_ADC_SCALE = 2.0/4096` |
| 蜂鸣器     | **39** | 有源蜂鸣器，给电即响                            |
| 蓝灯      | **14** | ESP-FC 只驱动单色灯，红 41 / 绿 7 未用           |
| 板载 LED  | **48** | 未驱动                                   |

> 🔴 **电池电压系数是硬件决定的**：VBAT 经 1:2 分压到 GPIO2，  
> 所以 `Vbat = Vadc × 2`，`ESPFC_ADC_SCALE` 必须填 `2.0f / 4096`。  
> 填成 `3.3f/4096`（上游 ESP32S3 的默认值）会导致显示电压**只有真实值的一半**，  
> 低压告警永远不响 —— 这是个会咬人的坑。

## 四、🔴 电机类型：为什么必须开 `ESPFC_DEV_PRESET_BRUSHED`

这是本次适配**唯一一个"不编译就完全飞不起来"的决定**，单独一节讲。

### 4.1 问题

上游 ESP-FC 面向无刷四轴，默认输出协议是 **DShot300**：

```ini
; 上游 platformio.ini 里这行是注释掉的（默认即 DShot）
;  -DESPFC_DEV_PRESET_DSHOT
```

DShot 是一套**数字协议**：每帧先拉低再拉高、用占空比编码 0/1，  
需要**智能电调（ESC）**&#x91CC;有解码芯片才能听懂。

8520 空心杯电机配的是**廉价有刷电调**（本质就是"开关 + 二极管 + 换向器"），  
它只认**传统 PWM 脉宽**（1000~2000 µs）。  
给它发 DShot = 门铃上贴张纸条写"DingDong"，它毫无反应 ⇒ **四个电机全停转**。

### 4.2 解法

`ESPFC_DEV_PRESET_BRUSHED` 宏让 `ModelConfig.h` 做三件事：

```cpp
output.protocol = ESC_PROTOCOL_BRUSHED;   // 协议换成 PWM
output.async = true;                       // 异步（LEDC 硬件）输出，不占 CPU
output.rate = 3000;                        // 刷新率 3 kHz
```

同时我们**故意没有**在 `TargetESP32s3YaoKun.h` 里定义 `ESPFC_DSHOT_TELEMETRY`  
（上游 `TargetESP32s3.h` 里有那行）—— DShot 双向回读转速只对智能电调有意义，  
对 PWM 电调无效，误开会白白占用 DMA 与一路串口。

### 4.3 验证

烧完后地面站 → 电机测试，**必须听到四个电机都响**。  
只有一个响 → 检查 `ESPFC_OUTPUT_0..3` 的顺序（GPIO 6/5/15/16）；  
全都不响 → 检查是否漏了 `-DESPFC_DEV_PRESET_BRUSHED`。

## 五、Flash / PSRAM 选型（🔴 用错直接 panic）

耀坤 S3 有两种模组，**只差 Flash 大小与 PSRAM 类型**，引脚完全相同。

| 项             | `[env:esp32s3_yaokun]`（立创 R8N8）★ | `[env:esp32s3_yaokun_n4r2]`（Supermini） |
| ------------- | -------------------------------- | -------------------------------------- |
| Flash         | 8 MB                             | 4 MB                                   |
| 分区表           | `default_8MB.csv`                | `partitions_4M_nota.csv`               |
| PSRAM         | 8 MB **OPI（八线）**                 | 2 MB **QIO（四线）**                       |
| `memory_type` | `qio_opi`                        | `qio`                                  |
| `flash_size`  | `8MB`                            | `4MB`                                  |

**选错的两种典型死法（都已经踩过）：**

1. **N4R2 刷了 R8N8 参数** → app 超出 4MB 分区边界 + OPI 初始化探测失败  
   → 芯片上电直接 `panic`，**没有任何串口输出**，地面站完全搜不到板子。
2. **R8N8 刷了 N4R2 参数** → 能启动但 Flash 只能用一半，且 PSRAM 类型填 `qio`  
   而实际是 OPI，运行一段时间后随机重启。

> 判断方法：看模组丝印。`R8N8` = 8MB Flash + 8MB PSRAM；  
> `N4R2` = 4MB Flash + 2MB PSRAM。

## 七、三级验证流程（无实物飞行的前提下）

用户明确要求"不做真机测试"，以下是**在台架/插电脑上就能做完**的三级验证：

### 一级：编译期验证（✅ 本次已完成）

```bash
cd Firmware
pio run -e esp32s3_yaokun
```

- 退出码 0
- 产物 `.pio/build/esp32s3_yaokun/firmware.bin` 存在
- 编译日志中 `ModelConfig` 生效（可见 BRUSHED 预设被应用）

### 二级：烧录 + 串口日志（插上电脑即可做）

1. `pio run -e esp32s3_yaokun -t upload -t monitor`
2. 开机应看到 ESP-FC 的 CLI 提示符与版本横幅
3. 在 CLI 里查固件实际认到的引脚：

```
status          # 看各串口功能分配
settings        # 看混控 / 电机协议
```

1. **不装桨**的前提下，接通电池，地面站 → 电机测试，四个电机应全响

> #### ⚠️ 2026-10-18 台架实测：ROM 有日志、应用层无输出（**待用户复核**）
>
> **已确认正常的部分**：
>
> - 编译 `SUCCESS`，产物齐全（bootloader / partitions / boot_app0 / firmware）
> - 烧录 `SUCCESS`，`Hash of data verified`，写入 995,360 B 到 `0x10000`
> - 上电 ROM 日志正常打印，关键行：  
>   `rst:0x15 (USB_UART_CHIP_RESET), boot:0x9 (SPI_FAST_FLASH_BOOT)`、  
>   `mode:DIO, clock div:1` —— **DIO 与我们镜像头里的 SPI 模式一致**，说明  
>   Flash / 分区表 / bootloader 三段都对，芯片正常跳进 bootloader 了
>
> **现象**：ROM 日志之后没有任何应用层输出。敲 `\r\n`、`status\r\n` 也无回显。
>
> **测试条件**：仅 USB 供电（未接电池），COM28 = `VID_303A&PID_1001`（Espressif  
> 原生 HWCDC，正好就是 `SERIAL_USB` 调试口）。
>
> **最可能的三个原因（按概率排序）**：
>
> 1. **电池未接** —— ESP-FC 的 IMU 校准状态 / 部分 Device 的 `begin()` 会在  
>    检测到低电压时挂起。USB 供电时 GPIO2 上是 0V，`VoltageSensor` 一直报 0V。  
>    ⇒ **接上电池再抓一次日志**，这是最先该试的。
> 2. **HWCDC 的 "CDC On Boot" 时序** —— 芯片启动（~0.4 s）远早于 Windows  
>    枚举出 COM 口，早期字节会被丢弃。⇒ **先打开串口监视器，再按 RST 复位**，  
>    不要先复位后开端口。
> 3. **CLI 走的是 UART0 而非 USB** —— 若 `ESPFC_SERIAL_DEBUG_PORT` 想改成  
>    `SERIAL_0`，需要外接 USB-TTL 到 GPIO43/44 才能看到输出。
>
> **判定方法**：接电池 + 先开端口再复位。若仍无输出，  
> 用 esptool 回读 app 段首字节确认镜像完整：
>
> ```bash
> esptool --chip esp32s3 --port COM28 read_flash 0x10000 0x200 app_hdr.bin
> # 首字节必须是 E9（ESP 镜像魔数）
> ```
>
> **这一步不影响交付**：编译与烧录两个环节已全部验证通过，  
> 串口应用层输出属于"上电后的运行时行为"，需要接电池才能完整验证。

### 三级：桌面悬空检查（不拆桨也能做的大部分项）

- 手动左右/前后倾斜机身，地面站姿态仪应同向翻转
- 拔掉 IMU 排线 → 地面站应报"传感器失联"而不是静默
- 断开接收机 → 应进入 failsafe，电机降油门

> ⚠️ **首次带桨试飞请务必**：空旷场地、装保护圈、留足退让空间、低空慢速。  
> 本飞控是纯姿态自稳 + 手动油门，**松杆不会悬停、松油门就掉高度**。

## 八、故障排查

| 现象           | 最可能原因                           | 处理                                           |
| ------------ | ------------------------------- | -------------------------------------------- |
| 地面站完全搜不到板子   | env 选错（Flash/PSRAM 不匹配）         | 换`esp32s3_yaokun` 或 `esp32s3_yaokun_n4r2` 重烧 |
| 烧录后停在下载模式    | USB CDC 没枚举出 COM                | 按住 BOOT 再复位；或改用 UART0（43/44）                 |
| 上电无串口输出      | Flash/PSRAM 参数错→ panic          | 核对 §五 表格                                     |
| 四个电机都不转      | 漏了 `-DESPFC_DEV_PRESET_BRUSHED` | 加上重新编译                                       |
| 只有一个电机转      | 电机顺序/接线错                        | 核对 §3.1；确认电调接在6/5/15/16                      |
| 电机全转但力度极小    | 电池电压采样系数错→ 认为低压                 | 核对 `ESPFC_ADC_SCALE = 2.0f/4096`             |
| 地面站电压显示只有一半  | 同上，`memory_type`/scale 错        | 同上                                           |
| 姿态不动 / 传感器失联 | IMU 片选错（V1=17 / V2=42）          | 改 `ESPFC_SPI_CS_GYRO` 后重编                    |
| 蜂鸣器常鸣        | 引脚被当电机脚（用的是上游固件）                | 确认烧的是耀坤 env，不是上游 `esp32s3`                   |
| SBUS 无信号     | 接收机没供电 / TX-RX 接反               | SBUS 是**单线**，只需共地 + 信号线到 GPIO1               |
| ELRS 接收机无数据  | 协议没设成 CRSF                      | 地面站把 UART2 协议改为 CRSF                         |

## 九、CLI 快速命令（插上电脑就能用）

ESP-FC 自带命令行接口，MSP 或 USB CDC 上都能敲：

| 命令                  | 作用                     |
| ------------------- | ---------------------- |
| `status`            | 打印当前状态摘要（飞行/解锁/传感器）    |
| `dump`              | 导出完整配置，用于备份与对比         |
| `set <参数> <值>`      | 修改参数                   |
| `save`              | 参数写入 Flash（⚠️ 会持久化，慎改） |
| `bl` / `bootloader` | 重启进下载模式                |
| `defaults`          | 恢复出厂参数                 |

> 参数持久化在 NVS 区（0x9000）。烧录时若用整片擦除会把 NVS 一起清掉，  
> 建议用 **分片烧录**（只写 bootloader / partitions / app 段）。

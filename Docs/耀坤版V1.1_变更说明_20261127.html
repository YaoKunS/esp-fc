二、三项代码 / 工具改动

2.1 蜂鸣器出厂极性（008459a）

现象：耀坤 S3 与火龙果 2.0 刷当前固件后，蜂鸣器一上电就持续鸣叫。用户实测CLI set pin_buzzer_invert 0 后恢复正常，要求把这个值固化进出厂默认。

根因：两板均为高电平触发有源蜂鸣器（S8050 驱动，给 High 响 / 给 Low 不响；S3 GPIO39、火龙果 GPIO25）。上游 BuzzerConfig.inverted 默认 true，是为「低电平触发」板设计的，导致 Buzzer::begin() 上电写 High —— 对高电平触发板就是持续通电常鸣。

改动：

  • Firmware/lib/Espfc/src/ModelConfig.h：让 inverted 支持板级宏覆盖，未定义宏时 仍为上游原值 true：
  #ifdef ESPFC_BUZZER_INVERTED
    int8_t inverted = ESPFC_BUZZER_INVERTED;
  #else
    int8_t inverted = true;
  #endif
    int32_t beeperMask;   // 保持上游原样，无初始化器
  • Target/TargetESP32s3YaoKun.h、Target/TargetESP32HLG20.h：各自定义 #define ESPFC_BUZZER_INVERTED 0，并写明「只摆正静止电平、音效灯效不碰」。

为什么不做全局默认值修改：仓库还含 `esp32 / esp32s3 / esp32s2 / esp32c3 /esp8266 / rp2040 等上游原版 env，极性未必与耀坤板一致，全局改 false` 会连带改坏其它板。板级宏是改动面最小的方案。

效果：上电写 Low（静止不响），需要响时仍由各蜂鸣事件写 High。等价于把用户手动set pin_buzzer_invert 0 的效果固化进出厂默认值，除此之外与旧固件行为完全一致。

2.2 打包布局按板型区分（9940d79）

问题：早先 merged.bin 把两板 bootloader 都摆到镜像偏移 0x0。经典 ESP32（火龙果 / WROOM-32）的 ROM 固定从 flash 0x1000 读 bootloader，整片镜像烧到 0x0后物理 0x1000 处无 0xE9 镜像头，芯片上电不启动。

改动（Firmware/tools/pack_release.py）：

  • BOARDS 新增 boot_addr：s3 = 0x0、hlg20 = 0x1000；
  • build_context() 遍历 SEGMENTS 时按板型覆盖 bootloader 地址，merge_bin() 缓冲区整体初始化为 0xFF，空隙自动填对；
  • 火龙果中英模板的「方式 B 分片烧录」0x0 → 0x1000；「方式 A 单文件」保持 0x0，并补「两个地址别弄混」提示；产物 / 地址表与合并布局说明同步修正。

地址口径（务必区分）：

场景耀坤 S3 (ESP32-S3)火龙果 2.0 (经典 ESP32)
单文件 merged.bin 烧录地址0x00x0
bootloader 在 merged 镜像内部偏移0x00x1000（0x0~0x1000 填 0xFF）
单独烧裸 bootloader.bin 的地址0x00x1000

依据：PlatformIO 自动生成的 firmware_0x00.bin、以及耀坤自研飞控火龙果版已验证可启动的 merged.bin 均为上述布局。

2.3 MSP 220 防护 —— 本次最新改动（0376595）

现象：两块 PCB 的陀螺仪同时「无法识别」。

定位：并非固件结构错位，而是 NVS 里 gyro_dev = NONE。CLI get gyro_dev 两板均为 NONE，而 gyro_bus / gyro_align / baro / mag 全部正常，启动日志完全没有GYRO INIT / ACCEL INIT 行。

根因链（死循环）：MspProcessor.cpp 中 MSP_SET_SENSOR_ALIGNMENT(220) 原实现：

uint8_t gyroEnableMask = m.readU8();                       // gyro_enable_mask
_model.config.gyro.dev = gyroEnableMask & 1 ? GYRO_AUTO : GYRO_NONE;

而 MSP_SENSOR_ALIGNMENT(126) 读回的 gyro_enable_mask 不是用户配置，是同文件上方写的 _model.state.gyro.present ? 1 : 0 —— 一个运行时探测结果。于是：

某次开机陀螺仪暂时没探测到（模块未插好、上电时序、配置器在启动瞬间就连接）
→ 126 读回 0 → 用户在 BF 配置器点「保存」把整帧写回 220 → dev 被改成
GYRO_NONE → 经 MSP_EEPROM_WRITE / save() 固化进 NVS → 之后每次开机
Hardware::detectGyro() 首行 if (dev == GYRO_NONE) return; 直接早退 →
126 读回仍是 0，「再保存一次」也永远无法自愈。

改动（Firmware/lib/Espfc/src/Connect/MspProcessor.cpp，约 624 行处）：只消费该字节、不再改写 config.gyro.dev，并补 35 行中文注释记录成因与约束：

if (m.remain() >= 1)
{
  m.readU8(); // gyro_enable_mask：只消费、故意不使用
}

关键决策：

  • 为什么是「忽略」而不是「mask=0 时强制设回 AUTO」：ESP-FC 是单 IMU + 自动探测架构，BF 的多陀螺仪选通掩码在本固件里没有对应语义。保持原值不动能同时 保住三种情况 —— 出厂 GYRO_AUTO 不会被配置器保存动作关掉；用户显式 set gyro_dev NONE + save 不会被覆盖；手动选定的具体型号不会被冲成 AUTO。
  • 为什么这个 readU8() 不能删：220 帧里 mask 之后还可能跟 6 字节 （gyro1 roll/pitch/yaw）。不消费这一字节会让下面的 if (m.remain() >= 6) 帧指针错位，后续对齐 / 角度读出脏数据。
  • 边界：本改动只防止「再次被写坏」，不会把 NVS 里已有的 GYRO_NONE 自动改回 AUTO。历史脏值仍需 CLI set gyro_dev AUTO + save 修一次。

同时更新 pack_release.py 中四个 V1.1 章节（S3 中/英、火龙果中/英），同步补上MSP 防护与蜂鸣器修复说明并重打两板 merged.bin。

七、升级 / 使用建议

  1. 已有 gyro_dev=NONE 脏值的板子：本固件不会自动改回。刷完后在 CLI 执行 set gyro_dev AUTO → set accel_dev AUTO → save → reboot，再 status 确认 有 GYRO INIT / ACCEL INIT。此操作只需一次。
  2. 换板型刷机必做：defaults → save → reboot，避免 NVS 残留引脚值 （如 S3 的 CS=42）覆盖本板默认。
  3. 已标定过的机器：用「方式 B 分片烧录」，不要用 0x0 整片刷 —— 整片刷会把 0x9000~0xE000 的 nvs 区清成 0xFF，PID、调参、加速度计标定值全部丢失。
  4. 配置器使用：修复后，在配置器里点「保存」不再会关闭陀螺仪；gyro_align 等对齐项仍可正常读写保存。

八、明确未改动项（边界）

  • beeperMask 保持上游原样（无初始化器）；开机提示音 BUZZER_SYSTEM_INIT、 陀螺仪校准音、RX 丢失 / 恢复、低电压、解锁 / 上锁等全部状态音效， 以及全部 LED 灯效逻辑与配置，一字未改。
  • 传感器自动探测、IMU 朝向自动分档（I2C 6050 → CW270、SPI 6500 → CW90）、 MS5611 气压计驱动、两板引脚表与编译宏，均未改动。
  • 除耀坤 S3 与火龙果 2.0 两块板外，其它上游 env 的 BuzzerConfig 默认值未改动。
  • 不自动回写 / 清理用户 NVS 中的历史配置；不新增开机静音、不新增任何默认掩码。

读完本文你应该能回答三个问题：改了什么、为什么必须改、怎么确认改对了。

一、一句话结论

上游 ESP-FC 的 ESP32-S3 板级定义是给通用 S3 模板板（Lolin S3 Mini 一类）写的，
里面全是占位引脚（电机 39/40/41/42、SPI 12/11/13、I2C SCL=10），
与耀坤 S3 的 PCB 布线一对不上。直接烧上游固件的结果是：
四电机没输出、IMU 读不到、GPIO39 蜂鸣器被当成电机脚、电池电压读数偏差一倍。

本版新增独立板级定义 TargetESP32s3YaoKun.h + 独立编译环境 esp32s3_yaokun，
把引脚逐条对齐 xlsx 清单，并针对 8520 有刷电机强制启用 PWM（BRUSHED）输出协议。
上游 [env:esp32s3] 一行未改，两套固件可随时切换对比回归。

⚠️ 通道序号 ≠ 板上丝印序号：Betaflight QuadX 混控的电机序号是
1=右后、2=右前、3=左后、4=左前，与丝印 MOT1_FR/MOT2_RR 差一个交叉。
2026-10-24 台架实测：按丝印配（OUTPUT_0=6）会横滚/俯仰反向，对调后正确。

⚠️ 上游把 GPIO39/40/41/42 当电机脚，而耀坤板上
39 = 蜂鸣器、41 = 红灯、42 = V2 板的 MPU6500 片选。
不改的后果不是"电机不转"这么轻 —— 是蜂鸣器常鸣 + IMU 片选被拉乱。

3.4 其它

功能GPIO备注
VBAT 采样21:2 分压 ⇒ ESPFC_ADC_SCALE = 2.0/4096

🔴 电池电压系数是硬件决定的：VBAT 经 1:2 分压到 GPIO2，
所以 Vbat = Vadc × 2，ESPFC_ADC_SCALE 必须填 2.0f / 4096。
填成 3.3f/4096（上游 ESP32S3 的默认值）会导致显示电压只有真实值的一半，
低压告警永远不响 —— 这是个会咬人的坑。

四、🔴 电机类型：为什么必须开 ESPFC_DEV_PRESET_BRUSHED

这是本次适配唯一一个"不编译就完全飞不起来"的决定，单独一节讲。

4.1 问题

上游 ESP-FC 面向无刷四轴，默认输出协议是 DShot300：

; 上游 platformio.ini 里这行是注释掉的（默认即 DShot）
;  -DESPFC_DEV_PRESET_DSHOT

DShot 是一套数字协议：每帧先拉低再拉高、用占空比编码 0/1，
需要智能电调（ESC）&#x91CC;有解码芯片才能听懂。

8520 空心杯电机配的是廉价有刷电调（本质就是"开关 + 二极管 + 换向器"），
它只认传统 PWM 脉宽（1000~2000 µs）。
给它发 DShot = 门铃上贴张纸条写"DingDong"，它毫无反应 ⇒ 四个电机全停转。

4.2 解法

ESPFC_DEV_PRESET_BRUSHED 宏让 ModelConfig.h 做三件事：

output.protocol = ESC_PROTOCOL_BRUSHED;   // 协议换成 PWM
output.async = true;                       // 异步（LEDC 硬件）输出，不占 CPU
output.rate = 3000;                        // 刷新率 3 kHz

同时我们故意没有在 TargetESP32s3YaoKun.h 里定义 ESPFC_DSHOT_TELEMETRY
（上游 TargetESP32s3.h 里有那行）—— DShot 双向回读转速只对智能电调有意义，
对 PWM 电调无效，误开会白白占用 DMA 与一路串口。

4.3 验证

烧完后地面站 → 电机测试，必须听到四个电机都响。
只有一个响 → 检查 ESPFC_OUTPUT_0..3 的顺序（GPIO 5/6/15/16）；
全都不响 → 检查是否漏了 -DESPFC_DEV_PRESET_BRUSHED。

五、IMU 安装朝向自动分档（v1.0.1 新增，🧭）

5.1 问题与解法

耀坤 S3 PCB V2 上两种 IMU 模块的贴装/插装方向都不是"零旋转"，
直接用出厂默认（gyro_align=DEFAULT 不旋转）会导致 BF 配置器 3D 姿态错。

v1.0.1 起，固件在每次探测陀螺仪时自动按总线分档：

探测结果自动档位实测依据（BF 配置器 3D 模型，2026-11-26）
MPU6050（I2C 排母）CW270实物抬头 → 3D 抬头、实物右倾 → 3D 右倾
MPU6500（SPI 座）CW90同上

生效规则：仅当 gyro_align 仍为出厂默认 DEFAULT 时自动覆盖，每次开机探测都执行，
排母换模块立即生效；用户 CLI/BF 配置器显式设过的值（≠DEFAULT）永远优先，不会被覆盖。

5.2 🔴 插装方向是第一嫌疑（踩坑实录）

排母/SPI 座允许 180° 插装，模块插的方向一变，正确档位就跟着变。
排障时若见 pitch/roll 双双反相（实物抬头 3D 低头、实物左倾 3D 右倾）
= 传感器系绕 Z 轴恰差 180°，先检查模块有没有被反向插过，再谈参数。

判定小技巧：板子水平静止时读加速度计，z 轴 ≈ +1g 说明芯片没装反面
（排除 FLIP 系对齐）；若 z ≈ -1g 才需要考虑 FLIP 系档位。

5.3 现场试档方法（不用重新编译）

gyro_align 是每个采样周期实时读取的，CLI set 后立即生效（不 save 也生效）：

set gyro_align CW270    # 改完直接看 BF 3D，不对就换下一档
save                    # 确认对了才 save（⚠️ 会固化，见下）

⚠️ 任何 save 都会把当时的值固化进 NVS。显式值（≠DEFAULT）会永久压制
自动分档——换 IMU 类型后它会拿旧值去转新模块，姿态就错了。
恢复自动分档：set gyro_align DEFAULT → save。

六、MS5611 气压计支持（v1.0.1 新增，🆕）

6.1 驱动能力

Device/Baro/BaroMS5611.hpp/.cpp（全新驱动，上游无此文件）：

  • I2C 地址 0x76/0x77 全自动探测，OSR4096 高精度档（气压更新率约 51 Hz）
  • 一阶 + 二阶温度补偿，PROM 校准系数带 CRC-4 校验
  • 双数学模式，新 CLI 参数 baro_math：
    • -1 自动判别（默认）：CRC 过 → datasheet 公式；不过 → AN520 公式
    • 0 强制 MS5611 datasheet 公式；1 强制 MS5607/AN520 系公式

6.2 🔴 GY-63 兼容模块的坑：芯片可能是 MS5607

市售 GY-63 模块多贴 MS5607/AN520 系芯片，其压力校准系数与 MS5611 差 2 倍，
用错公式时气压读数恰为真实值的一半（约 50 kPa）。
baro_math=-1 的自动判别（靠 PROM CRC-4）可免手动分辨；
判别过程数据可从 CLI debug[4..7]（DEBUG 模式设 BARO）观察。

启用：CLI set baro_dev MS5611 → save。台架实测（2026-11-26）：
GY-63 兼容模块气压 101.4 kPa 稳定无漂移。

6.3 接线

模块走 I2C（SDA=9 / SCL=8），与 MPU6050 共总线。
⚠️ 模块接线不良会拉死整条 I2C 总线（连 MPU6050 都读不到），
I2C 全灭时先拔外接模块再排查。

6.4 V1.1：默认自动探测与开机身份横幅

出厂默认全部 AUTO（V1.1 起）：gyro_dev / accel_dev / gyro_bus /baro_dev / baro_bus / mag_dev / mag_bus 均为 AUTO，插上模块即自动探测，无需任何 CLI 配置。自动探测覆盖：

  • 气压计：BMP280 / BMP085 / SPL06-001 / MS5611（MS5611 仅 I2C，SPI 口探测前三者）
  • 磁力计：HMC5883L / QMC5883L / QMC5883P / AK8963（I2C 或陀螺仪从总线）
  • IMU：MPU6050 / MPU6500 / MPU9250 / ICM20602 / ICM42688 / BMI160 / LSM6DSO

开机 IDENTITY 横幅（V1.1 新增）：上电第一屏在 MSP 串口打印多行身份串（产品名 / 版本 V1.1 / 编译时间 / 作者 / B 站 / 立创 / 淘宝 / GitHub），与耀坤自研飞控、Flix 耀坤整理版口径一致。S3 版不含任何火龙果链接——火龙果是独立品牌，其硬件与原项目归微辣火龙果（malagis），本固件只做适配维护。

七、Flash / PSRAM 选型（🔴 用错直接 panic）

耀坤 S3 有两种模组，只差 Flash 大小与 PSRAM 类型，引脚完全相同。

项[env:esp32s3_yaokun]（立创 R8N8）★[env:esp32s3_yaokun_n4r2]（Supermini）
Flash8 MB4 MB
分区表default_8MB.csvpartitions_4M_nota.csv
PSRAM8 MB OPI（八线）2 MB QIO（四线）
memory_typeqio_opiqio
flash_size8MB4MB

选错的两种典型死法（都已经踩过）：

  1. N4R2 刷了 R8N8 参数 → app 超出 4MB 分区边界 + OPI 初始化探测失败 → 芯片上电直接 panic，没有任何串口输出，地面站完全搜不到板子。
  2. R8N8 刷了 N4R2 参数 → 能启动但 Flash 只能用一半，且 PSRAM 类型填 qio 而实际是 OPI，运行一段时间后随机重启。

判断方法：看模组丝印。R8N8 = 8MB Flash + 8MB PSRAM；
N4R2 = 4MB Flash + 2MB PSRAM。

用户明确要求"不做真机测试"，以下是在台架/插电脑上就能做完的三级验证：

一级：编译期验证（✅ 本次已完成）

cd Firmware
pio run -e esp32s3_yaokun

  • 产物 .pio/build/esp32s3_yaokun/firmware.bin 存在
  • 编译日志中 ModelConfig 生效（可见 BRUSHED 预设被应用）

二级：烧录 + 串口日志（插上电脑即可做）

  1. pio run -e esp32s3_yaokun -t upload -t monitor
  2. 开机应看到 ESP-FC 的 CLI 提示符与版本横幅
  3. 在 CLI 里查固件实际认到的引脚：
status          # 看各串口功能分配
settings        # 看混控 / 电机协议
  1. 不装桨的前提下，接通电池，地面站 → 电机测试，四个电机应全响

#### ✅ 2026-10-18 台架实测：ROM 有日志、应用层无输出（已解决）
结论（2026-11-26 补记）：该悬案后来复测不复现——接上电池、按正常顺序
开端口即可看到应用层输出；地面站（COM13@115200 MSP）、CLI、固件推送均
已实测跑通。当时的三个嫌疑（电池未接 / HWCDC 时序 / CLI 走 UART0）中，
前两条与实测吻合。原文保留如下供回溯。
已确认正常的部分：
• 编译 SUCCESS，产物齐全（bootloader / partitions / boot_app0 / firmware）
• 烧录 SUCCESS，Hash of data verified，写入 995,360 B 到 0x10000
• 上电 ROM 日志正常打印，关键行：
rst:0x15 (USB_UART_CHIP_RESET), boot:0x9 (SPI_FAST_FLASH_BOOT)、
mode:DIO, clock div:1 —— DIO 与我们镜像头里的 SPI 模式一致，说明
Flash / 分区表 / bootloader 三段都对，芯片正常跳进 bootloader 了
现象：ROM 日志之后没有任何应用层输出。敲 \r\n、status\r\n 也无回显。
测试条件：仅 USB 供电（未接电池），COM28 = VID_303A&PID_1001（Espressif
原生 HWCDC，正好就是 SERIAL_USB 调试口）。
最可能的三个原因（按概率排序）：
1. 电池未接 —— ESP-FC 的 IMU 校准状态 / 部分 Device 的 begin() 会在
检测到低电压时挂起。USB 供电时 GPIO2 上是 0V，VoltageSensor 一直报 0V。
⇒ 接上电池再抓一次日志，这是最先该试的。
2. HWCDC 的 "CDC On Boot" 时序 —— 芯片启动（~0.4 s）远早于 Windows
枚举出 COM 口，早期字节会被丢弃。⇒ 先打开串口监视器，再按 RST 复位，
不要先复位后开端口。
3. CLI 走的是 UART0 而非 USB —— 若 ESPFC_SERIAL_DEBUG_PORT 想改成
SERIAL_0，需要外接 USB-TTL 到 GPIO43/44 才能看到输出。
判定方法：接电池 + 先开端口再复位。若仍无输出，
用 esptool 回读 app 段首字节确认镜像完整：
```bash
esptool --chip esp32s3 --port COM28 read_flash 0x10000 0x200 app_hdr.bin
# 首字节必须是 E9（ESP 镜像魔数）
```
这一步不影响交付：编译与烧录两个环节已全部验证通过，
串口应用层输出属于"上电后的运行时行为"，需要接电池才能完整验证。

三级：桌面悬空检查（不拆桨也能做的大部分项）

  • 手动左右/前后倾斜机身，地面站姿态仪应同向翻转
  • 拔掉 IMU 排线 → 地面站应报"传感器失联"而不是静默
  • 断开接收机 → 应进入 failsafe，电机降油门

⚠️ 首次带桨试飞请务必：空旷场地、装保护圈、留足退让空间、低空慢速。
本飞控是纯姿态自稳 + 手动油门，松杆不会悬停、松油门就掉高度。

十、故障排查

现象最可能原因处理
地面站完全搜不到板子env 选错（Flash/PSRAM 不匹配）换esp32s3_yaokun 或 esp32s3_yaokun_n4r2 重烧
烧录后停在下载模式USB CDC 没枚举出 COM按住 BOOT 再复位；或改用 UART0（43/44）
上电无串口输出Flash/PSRAM 参数错→ panic核对 §七 表格
四个电机都不转漏了 -DESPFC_DEV_PRESET_BRUSHED加上重新编译
只有一个电机转电机顺序/接线错核对 §3.1；确认电调接在5/6/15/16
电机全转但力度极小电池电压采样系数错→ 认为低压核对 ESPFC_ADC_SCALE = 2.0f/4096
地面站电压显示只有一半同上，memory_type/scale 错同上
姿态不动 / 传感器失联IMU 片选错v1.0.1 默认 CS=42；V1 板 set pin_spi_cs_0 17 → save
pitch/roll 双反相（抬头→低头、左倾→右倾）模块 180° 反插 / gyro_align 显式值残留固定插装方向；set gyro_align DEFAULT → save 恢复自动分档（§五）
换 IMU 模块后姿态错 90°/180°NVS 固化了旧 gyro_align 显式值set gyro_align DEFAULT → save（显式值会压制自动分档）
气压读数恰为一半（约 50 kPa）GY-63 实贴 MS5607/AN520 系，公式用错set baro_math -1（CRC 自动判别）或 1（§六）
I2C 全灭（陀螺/气压全 FF）外接模块接线不良拉死总线拔掉外接模块逐个排除；I2C 已降速 800（i2c_speed）
蜂鸣器常鸣引脚被当电机脚（用的是上游固件）确认烧的是耀坤 env，不是上游 esp32s3
SBUS 无信号接收机没供电 / TX-RX 接反SBUS 是单线，只需共地 + 信号线到 GPIO1
ELRS 接收机无数据协议没设成 CRSF地面站把 UART2 协议改为 CRSF

十一、CLI 快速命令（插上电脑就能用）

ESP-FC 自带命令行接口，MSP 或 USB CDC 上都能敲：

命令作用
status打印当前状态摘要（飞行/解锁/传感器）
dump导出完整配置，用于备份与对比
set <参数> <值>修改参数
save参数写入 Flash（⚠️ 会持久化，慎改）
bl / bootloader重启进下载模式
defaults恢复出厂参数

参数持久化在 NVS 区（0x9000）。烧录时若用整片擦除会把 NVS 一起清掉，
建议用 分片烧录（只写 bootloader / partitions / app 段）。

# 编译（默认 R8N8）
pio run -e esp32s3_yaokun

# 烧录 + 打开串口监视器

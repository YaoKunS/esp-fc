一、项目定位

ESP-FC 是一款运行在 ESP32 上的开源飞控固件，定位是迷你、低成本、高性能。 它最大的特色是协议兼容：固件实现的是标准的 Betaflight / Cleanflight MSP 协议 v2，所以市面上的 Betaflight Configurator 和 Cleanflight Configurator 可以直接连上、直接识别、直接调参 —— 不需要专用上位机。

本仓库是 rtlopez/esp-fc 的 耀坤整理版 + 耀坤 S3 硬件适配。目标是让耀坤自研的 S3 四轴 （配 8520 空心杯电机）用上这套成熟的开源内核。

上游原版（master）

ESP-FC 0.3.0 完整源码，一行未改。引脚定义面向 Lolin S3 Mini 等通用模板板， 支持 ESP32 / S2 / S3 / C3 / ESP8266 / RP2040 / RP2350 七种平台。

耀坤版（本分支）

在上游基础上新增独立板级定义 TargetESP32s3YaoKun.h 与独立编译环境 esp32s3_yaokun。算法层零改动。

为什么"算法层零改动"这么重要？
因为飞控里最容易出事的地方不是引脚，是姿态解算、角速度滤波、混控顺序、failsafe 判据。 这些逻辑上游已经在大量机型上验证过。我们只换"引脚和电机协议"， 把所有经过验证的数学部分原封不动留下 —— 这是本次适配风险最低的路径。

🔴 选错的两种死法（都已经踩过）
N4R2 刷了 R8N8 参数 → app 超出 4MB 分区边界 + OPI 初始化失败 → 芯片上电直接 panic，没有任何串口输出，地面站完全搜不到板子。

三、为什么必须重做引脚

3.1 上游 ESP32-S3 模板是什么

ESP-FC 0.3.0 的 Target/TargetESP32s3.h 是给 Lolin S3 Mini 这类通用模板板写的。它假定的是一块"标准 S3 开发板 + 外接电调"， 所有引脚都是方便记忆的占位值：

// 上游 TargetESP32s3.h（原样，一行未改）
#define ESPFC_INPUT_PIN 6        // ppm
#define ESPFC_OUTPUT_0 39
#define ESPFC_OUTPUT_1 40
#define ESPFC_OUTPUT_2 41
#define ESPFC_OUTPUT_3 42
#define ESPFC_SPI_0_SCK 12
#define ESPFC_SPI_0_MOSI 11
#define ESPFC_SPI_0_MISO 13
#define ESPFC_SPI_CS_GYRO 8
#define ESPFC_I2C_0_SCL 10
#define ESPFC_I2C_0_SDA 9
#define ESPFC_BUZZER_PIN 5
#define ESPFC_ADC_VBAT_PIN 1
#define ESPFC_LED_PIN -1

这套值跟耀坤 S3 的 PCB 布线几乎条条对不上。烧上去会发生什么：

  1. 四个电机一个都不转 —— 驱动 39/40/41/42，而电调接在 6/5/15/16
  2. 蜂鸣器常鸣 —— GPIO39 被当成电机 PWM 输出
  3. IMU 读不到 —— SPI 片选是 8、时钟是 12，而板上是 17/38
  4. 电池电压读数偏差一倍 —— ADC 接在 1 而板上是 2，且分压系数不同
  5. 最糟的是 39/40/41/42 中 GPIO42 还是 V2 板的 IMU 片选， 被高频 PWM 驱动后 IMU 数据彻底是噪声

3.2 我们的做法：新增，不修改

没有直接改 TargetESP32s3.h，而是新建一个文件，理由有三：

① 可回归

上游 [env:esp32s3] 保持原样， 随时能编一版做对比，定位"是我的适配错了还是上游变了"。

② 可合并

将来同步上游新版本时， TargetESP32s3.h 大概率会被改动；我们只在自己的文件里收敛冲突。

③ 可读

新人打开 TargetESP32s3YaoKun.h， 一眼就知道这块板长什么样，不用去猜 39 是电机还是蜂鸣器。

// Firmware/lib/Espfc/src/Target/Target.h —— 全部改动只有这3 行
#if defined(ESPFC_TARGET_YAOKUN)          // ← 耀坤智联新增
  #include "TargetESP32s3YaoKun.h"
#elif defined(ESP32C3)
#include "TargetESP32c3.h"
...
#elif defined(ESP32S3)
#include "TargetESP32s3.h"               // ← 上游原版，保持不变
#endif
为什么 ESPFC_TARGET_YAOKUN 的判断要放在 ESP32S3 前面？
因为该宏同时定义了 ESP32S3（芯片系列）和板级选择。 如果放在后面，条件永远轮不到它，编译会静默使用上游引脚 —— 烧上去才发现问题， 代价是拆桨、上电、试飞，全白费。

四、8520 空心杯电机适配

🔴 这是本次适配唯一一个"不编译就完全飞不起来"的决定，单独一节讲。

4.1 问题本质

ESP-FC 面向无刷四轴，默认输出协议是 DShot300。 DShot 是一套数字协议：每帧先把线拉低再拉高，用占空比编码 0 / 1， 中间还会插入 CRC。它需要智能电调（ESC）里有解码芯片才听得懂。

8520 空心杯电机配的是廉价有刷电调。所谓"电调"其实就是一个 开关 + 二极管 + 换向器，它只认传统的 PWM 脉宽（1000~2000 µs）。

类比 给门铃贴张纸条写"DingDong" 有刷电调收到 DShot 帧，理解为"有电=通"，全程无响应 → 四电机全停转

4.2 解法：-DESPFC_DEV_PRESET_BRUSHED

这个宏让 ModelConfig.h 在初始化时做三件事：

// ModelConfig.h（约 1160 行）
#ifdef ESPFC_DEV_PRESET_BRUSHED
      output.protocol = ESC_PROTOCOL_BRUSHED;   // 协议换成 PWM
      output.async = true;                       // 异步（LEDC 硬件）输出，不占 CPU
      output.rate = 3000;                        // 刷新率 3 kHz
#endif

同时，我们在 TargetESP32s3YaoKun.h 里 故意没有定义 ESPFC_DSHOT_TELEMETRY （上游 TargetESP32s3.h 里有那行）：

DShot 双向回读（bidirectional DShot）能让地面站显示实时转速， 但它只对智能电调有意义。对 PWM 电调，它会白白占用一路 DMA 与一个串口外设， 换来的功能是永远不触发的数据。

4.3 验证

1
地面站 → 电机测试不装桨，接通电池，四个电机必须全部响
2
只有一个响检查 ESPFC_OUTPUT_0..3 顺序与电调接线（应为 6/5/15/16）
3
全都不响检查编译命令是否带 -DESPFC_DEV_PRESET_BRUSHED

5.2 主循环

ESP-FC 的主循环在 src/main.cpp，结构极简：

int main()
{
  device.initBoard();      // 按 ModelConfig 的引脚默认值初始化所有外设
  device.init();           // 加载参数（若已保存则用保存值覆盖默认值）
  while (1) {
    device.step();         // ① 读传感器 ② 姿态解算 ③ PID ④ 混控 ⑤ 输出 PWM/DSHOT
    device.await();        // FreeRTOS 让出 CPU 给 Wi-Fi / USB 任务
  }
}

所有实际工作都在 Device::step() 里串起来。S3 是双核的， device.await() 让出核心后，Wi-Fi / ESP-NOW / USB 任务可以在另一核上跑， 这也是为什么我们的 Target 里明确不定义单核宏。

六、控制回路

ESP-FC 用的是标准的串级 PID，与 Betaflight 同构：

① 传感器 陀螺仪角速度 + 加速度计 MPU6500(SPI) 或 MPU6050(I2C)，SPI 可到 4 kHz
↓
② 滤波 低通 + 陷波（可动态） 有刷电机噪音大，插桨后建议开 3 组陷波
↓
③ 姿态 AHRS 融合出四元数 Madgwick / Mahony / Kalman / RTQF，互补滤波类
↓
④ PID 角度环 → 角速度环（串级） 外环给角度目标，内环跟角速度，比单环稳得多
↓
⑤ 混控 四电机分配 + 油门曲线 本板为 QUAD-X（默认）
↓
⑥ 输出 PWM / DShot 帧 ★ 本板走 PWM(GPIO 6/5/15/16)，异步 LEDC，3 kHz

6.1 与 Betaflight 参数的对应

因为实现了 MSP 协议，配置器里调的所有 PID / 滤波 / 电机参数 都是 Betaflight 的标准命名，不用重新学：

Betaflight 项含义本板建议初值
PID Profile角度环/速率环 PID先用默认，别乱调
Gyro LP Filter陀螺低通截止默认；有刷噪音大可降到 60 Hz
Dyn Notch Count动态陷波组数插桨后设 3
Motor Min/Max电机端点先用默认，地面站电机测试校准
Motor Output输出协议应显示 PWM / Brushed

七、传感器链路

7.1 双通路设计

ESP-FC 同时支持 SPI 与 I2C 两种 IMU 总线，由 ModelConfig 在启动时探测。 耀坤板两种都能用：

IMU 芯片总线SDA/SCL 或 SCK/MOSI/MISO片选最高速率
MPU6500SPI38 / 18 / 21174000 Hz
MPU6050I2CSDA 9 / SCL 8—2000 Hz
⚠️ SCL / SDA 千万别写反
SDA 是 GPIO9，SCL 是 GPIO8。写成 SCL 9 / SDA 8 的后果是 I2C 完全不通 —— 而且现象很迷惑：有时能"碰巧"读到，因为 I2C 是"时钟由主机拉低、 数据由主机拉高"的单线时序，SDA/SCL 接反时 ACK 有时仍能回来。
同一条教训在 Flix 工程也踩过一次 —— 两个项目、两块板、同一个坑，值得单独记一笔。

7.2 常见故障：IMU 读不到

按这个顺序排查，90% 的问题在前两步：

1
确认板型版本V1 板 CS=17；V2 板 CS=42。改错必然读不到
2
确认总线6500 走 SPI、6050 走 I2C。插错总线 = 完全没数据
3
确认接线SPI 还需 MISO/MOSI/SCK/CS 四根全接；I2C 需共地
4
确认滤波设置把 Gyro LP Filter 拉高会"看起来像没信号"，先恢复默认

八、MSP 协议与地面站

这是 ESP-FC 相比 Flix 那类自研飞控最大的实用优势： 用现成的 Betaflight Configurator。

8.1 支持的地面站

地面站支持说明
Betaflight Configurator✅首选。参数最全，UI 最新
Cleanflight Configurator✅老牌地面站，兼容
ELRS LUA 脚本 / OSD✅需 CRFLua 飞控协议支持
Betaflight 黑盒子分析✅需在 CLI 里开 Blackbox

8.2 连接方式（三选一）

① UART0（推荐）

GPIO43 = TX、GPIO44 = RX，115200 8N1。
刷完固件第一次上电就能看到日志，最适合排查问题。

② USB CDC

S3 原生 USB，Windows 会枚举出新的 COM 口。
不依赖 USB-UART 桥芯片，二次烧录也更稳。

③ Wi-Fi / ESP-NOW

连上飞控热点后可用 wifi 软串口下发 CLI 命令。
适合不方便插线时看状态。

④ ELRS

需把 UART2（11/12）协议设为 CRSF。
走 ELRS 全双工，还有双向遥测链路。

九、安全机制

ESP-FC 的安全逻辑与 Betaflight 同源，耀坤板上全部生效：

机制行为本板是否生效
解锁门控上电默认锁定，必须显式解锁（摇杆组合或 CLI）✅
接收机失联 failsafe油门置零 / 缓降（可在地面站配置）✅ SBUS 与 CRSF 均适用
IMU 失联检测读数异常时停止输出并告警✅
低电压告警按 ESPFC_ADC_SCALE 换算真实电压✅ 系数正确才准（见 §2.2）
油门限幅desaturate() 削顶后重新分配，保持姿态优先✅ 有刷电机尤其重要
校准流程加速度计 1G 校准、中位校准✅
关于拆桨验证校准
ESP-FC 的加速度计校准同样需要把机身摆放成六面。 如果固件是"一口气跑完 48 秒、中途不等人操作"的写法， 人手是跟不上的 —— 六面会采到同一个姿态，accScale 会塌到 1e-2 量级。
刷回本板前请确认你板子的 ca 命令是不是分段式（ca1~ca6）。

🔴 千万别烧 esp32s3（上游那个）到耀坤板上
它会驱动 GPIO39/40/41/42 当电机 —— 其中 39 是蜂鸣器， 你会听到开机就一直嗡嗡响，而且电机不动。这不是坏了，是烧错固件了。

10.2 耀坤 env 的关键编译宏

宏作用漏了会怎样
-DESPFC_TARGET_YAOKUN选耀坤引脚定义用上游引脚 → 电机不转 + 蜂鸣器常鸣
-DESPFC_DEV_PRESET_BRUSHED输出协议 = PWM发 DShot 给有刷电调 → 四电机全停
-DESP32S3芯片系列找不到平台定义
-DBOARD_HAS_PSRAM启用 PSRAM性能下降，黑盒子写入可能失败
-DARDUINO_USB_MODE=1USB 做 CDCUSB 口无串口，MSP 连不上
-DARDUINO_USB_CDC_ON_BOOT=1上电即枚举 CDC同上

10.3 分区表与 Flash 参数

见 §2.1 表格。要点重申：

  • R8N8 → default_8MB.csv + memory_type=qio_opi + flash_size=8MB
  • N4R2 → partitions_4M_nota.csv + memory_type=qio + flash_size=4MB
烧录时不要整片擦除
参数持久化在 NVS 区（0x9000）。整片从 0x0 连写会把它一起清掉， 你辛苦调好的 PID 与校准数据全丢。建议用 分片烧录：只写 bootloader（0x0）、partition table（0x8000）、boot_app0（0xE000）、 app（0x10000）。

十二、CLI 命令手册

ESP-FC 自带命令行接口，MSP 串口、USB CDC、Wi-Fi 软串口上都能敲。 这是不接地面站也能调试的关键。

命令作用备注

十三、故障排查

现象最可能根因处理
地面站完全搜不到板子env 选错，Flash/PSRAM 参数不匹配换 esp32s3_yaokun 或 _n4r2 重烧
烧录后停在下载模式USB CDC 没枚举出 COM按住 BOOT 复位；或改用 UART0(43/44)
上电无任何串口输出Flash/PSRAM 参数错 → panic对照 §2.1 核对
四个电机都不转漏 -DESPFC_DEV_PRESET_BRUSHED加上重新编译
只有一个电机转电机顺序 / 接线错核对 §2.2，应为 6/5/15/16
电机全转但力度极小电压采样系数错 → 误判低压核对 ESPFC_ADC_SCALE = 2.0f/4096
显示电压只有一半同上同上
姿态不动 / 传感器失联IMU 片选错（V1=17 / V2=42）改 ESPFC_SPI_CS_GYRO 重编
蜂鸣器常鸣烧的是上游 esp32s3 固件改烧 esp32s3_yaokun
SBUS 无信号接收机没供电 / 未共地SBUS 是单线：信号线到 GPIO1 + 共地
ELRS 接收机无数据协议没设成 CRSF地面站把 UART2 协议改为 CRSF
插桨后机身剧烈抖动电机噪音进 IMUCLI：set gyro_notch_count 3
校准后姿态仍飘校准没真正采到六面重跑校准，逐面静止 ≥2 秒

十四、飞行能力边界

★ 首次试飞前必读

ESP-FC 是纯姿态自稳 + 手动油门架构。

能做不能做 / 注意
姿态自稳（松杆自动回平）松杆不悬停 —— 姿态稳平但保持水平速度继续飘
三轴手动姿态控制松油门就掉高度
接收机失联自动降油门失联保护策略需在地面站确认（failsafe 模式）
黑盒子记录与回放无 GPS / 无地磁 / 无气压计 ⇒ 无定高、无定点、无航点
首次试飞建议
  1. 不装桨先完成所有地面验证（电机顺序、IMU 方向、failsafe）
  2. 装桨后先做悬空台架测试：低油门、用手轻扶、检查横滚/俯仰方向是否正确
  3. 首次带桨飞行：空旷场地、装保护圈、留足退让空间、低空慢速
  4. ⚠️ 横滚/俯仰方向写反是常见事故：推杆机身应向前倾。 方向反了请交换对应电调的 MOT3/MOT4 或调整混控顺序， 不要靠改 PID 修正
为什么本版不做定高？
耀坤 S3 板上有 GPIO3 / GPIO4 的 I2C1 总线，xlsx 上标注给 VL53L1X 激光测距用， 理论上可以做激光定高。但激光在 1 米以下对黑色地面和阳光环境很不稳定， 且本版未启用该总线。等飞机基本能稳飞了再考虑，顺序不能反。

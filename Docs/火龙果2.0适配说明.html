一、板子与三个"兄弟"固件的关系

火龙果 2.0 与耀坤 S3 无人机是同一系列、同一套 PCB 板框外形（2026-11-27 用户确认），自研飞控、Flix 耀坤整理版、ESP-FC V1.1 三个固件都已适配。因此：

  • IMU 安装方向完全一致 ⇒ ESP-FC 的朝向自动分档（按总线判，与板型无关）原样生效， 本适配不写任何方向代码；
  • 混控/电机布局沿用 S3 实测结论，只换引脚号；
  • 180° 反插坑同样存在（见 §四）。

ESP-FC 上游本来就支持经典 ESP32，且其 VSPI（18/19/23/CS5）与 I2C（21/22）恰好与火龙果一致 —— 所以本适配只改了一个 Target 头文件 + 一个编译环境，上游算法与耀坤 S3 适配层零改动。

串口裁剪（🔴 重要）：上游经典 ESP32 模板把 SERIAL_1 配在 TX33/RX32 —— 正好是右前/左前电机脚，SERIAL_2 配在 17/16 —— 是 I2C1 预留。本 Target 全部显式 -1，否则串口初始化会抢走电机。也不能定义 ESPFC_SERIAL_USB（经典片无原生 USB），调试口固定 SERIAL_UART_0。

四、🔴 经典 ESP32 的铁律（与 S3 版不同，逐条都咬过人）

  1. 只有 GPIO0~39：S3 版的 40 以上编号（如 V2 板 CS=42）在经典片上是 越界写寄存器（未定义行为）。本 Target 所有引脚 ≤39，不用的写 -1。
  2. GPIO6~11 是 Flash 专用，30 针 DevKit 上不能当 IO 用。
  3. ADC2 与 Wi-Fi 互斥：本固件 Wi-Fi 常开（ESP-NOW 无线 MSP）， 电池 ADC 必须落在 ADC1（32/33/34/35/36/39）。本板用 GPIO35=ADC1_CH7 ✅； 将来改板也绝不能把 ADC 挪到 ADC2 组（2/4/12~15/25~27），否则读数恒 0 → 误判低电 → 蜂鸣器无限急鸣。
  4. GPIO12 = MTDI strapping：悬空有内部弱下拉（复位读低 → 3.3V Flash 正常）。 将来接光流模块时，模块 MIS 的上拉会让 Flash 判成 1.8V → 反复重启； 解法 = 烧 eFuse 固定 3.3V（官方推荐、不可逆）或加 10k 下拉。
  5. GPIO2 既是 LED 又是 strapping：拉电流接法（GPIO2→电阻→LED→GND） 在复位期呈高阻，不影响 boot；别把它改成灌电流或外加高电平。

五、IMU 朝向自动分档（沿用，零新逻辑）

gyro_align=DEFAULT 时按总线自动选（与 S3 版同一套代码、同一组档位）：

  • I2C 排母 MPU6050 → CW270
  • SPI 座 MPU6500 → CW90

⚠️ 排母/SPI 座允许 180° 反插，插装方向一变正确档位就变（症状 = pitch/roll 双反相）。建议在模块和排母上做对位标记。现场试档：CLI set gyro_align CW270（6050）或 CW90（6500）实时生效——但 🔴 exit 退出 CLI 会触发重启，set 未 save 的值会丢失，所以试档期间不要退出 CLI，直接在 CLI 里连着 BF 看 3D；确认对了再 save。换 IMU 类型后用 set gyro_align DEFAULT → save 恢复自动分档。

六、验证流程（三级，照 S3 版老规矩）

级项目判据
1 编译pio run -e esp32_hlg20通过；app ≤ 1.25MB（本版 1.01MB）
2 烧录COM 口（板载 CH340），SHA 校验串口有启动横幅、BF 能识别
3 台架清 NVS（换板型刷机必做）CLI defaults → save → reboot
3 台架3D 姿态（6050 与 6500 各一次）抬头=抬头、右倾=右倾
3 台架电机测试（拆桨）推油门对角两颗同转、偏航正确一对加速
3 台架电压万用表对比，误差 < 0.2V
3 台架蜂鸣器 / LED上电提示音、状态灯正常
3 台架解锁门控未解锁推油门电机不转
